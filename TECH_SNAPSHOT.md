## 1. System Overview

Ordo AI is an AI-assisted work management product for executives. It ingests email and attachments, extracts text, and lets the user generate outputs (drafts, briefings, presentations, RACI plans) via Ava, an Anthropic Claude integration.

**Architecture**: Next.js 16 frontend (TypeScript, React 19) ↔ FastAPI backend (async SQLAlchemy + asyncpg) ↔ PostgreSQL 16. Files in AWS S3. Single EC2 host with nginx + pm2. Auto-deploy via GitHub Actions on push to `master`.

**Auth model**: httpOnly `access_token` JWT cookie, validated by `get_current_user` on every protected route. **Tenancy is enforced in service code only** — every read/write must filter by `owner_id == current_user.id`. No PostgreSQL row-level security. Admin auth is a separate realm (`admin_users` table) with its own cookie.

**Background processes**: three asyncio loops in the uvicorn process — `reminder_loop`, `weekly_digest_loop` (Mon 07:00 UTC), `daily_email_loop`. Document text extraction runs as fire-and-forget `asyncio.create_task`. **Single-worker assumption**.

## 4. Data Layer

PostgreSQL 16. UUID PKs everywhere except `stripe_events.id` (Stripe's event ID) and natural date keys (`ai_usage.week_start`). Migrations in `backend/migrations/versions/`; current head `c9d0e1f2a3b5_add_daily_email_fields_to_users`.

**Soft delete is partial** — only Document, Project, Task have `deleted_at`. User, Email, Reminder, GeneratedOutput, ChatMessage, TeamMember, AdminUser hard delete.

**Datetime conventions are mixed.** TZ-aware: User, Project, AdminUser, AdminAuditLog, Reminder.remind_at. Naive UTC: Task, TaskAssignment, Document, GeneratedOutput, ChatMessage, AIUsageRecord. Asyncpg rejects aware datetimes for the naive group — must use `datetime.utcnow()`.

**Key relationships**:
- User owns everything via `owner_id`/`user_id`, all CASCADE.
- Project → Task: 1:N, ON DELETE CASCADE.
- Project → Document: 1:N, ON DELETE SET NULL. **No M:N today** (Phase 1A target).
- Task → Document: 1:N via `documents.task_id` (SET NULL); plus reverse `tasks.source_doc_id`.
- Task ↔ TeamMember: M:N via `task_assignments`.
- Task → Task: self-referential `depends_on_id`.
- Email → EmailAttachment: 1:N (cascade).
- Email → Document: implicit via dual-write on ingestion (`documents.source_email_id`).

## 5. Integrations

- **AWS S3** — bucket from `settings.S3_BUCKET`. Direct browser-to-S3 upload via presigned PUT (10-min TTL); downloads via presigned GET (5-min TTL). URLs never persisted.
- **Anthropic Claude** — chat, outputs, delegation, daily/weekly emails. AI client in `app/core/ai/`.
- **Resend SMTP** — outbound transactional mail. "From" header reads live SMTP_* settings.
- **SendGrid Inbound Parse** — inbound email webhook at `/inbound/email`. nginx routes `/inbound/*` → backend (critical config).
- **Stripe** — Checkout, customer portal, webhook (`/webhook`, no `/api/v1` prefix). Idempotency via `stripe_events.id`. Free-plan gate at 15 AI calls/month.

## 7. Known Constraints / Design Decisions

- **No DB-level tenancy enforcement.** Service-layer filters only. Missing `owner_id` filter = data leak.
- **Soft delete only on Doc/Project/Task.** Other tables hard-delete.
- **Direct browser-to-S3 uploads.** Backend never proxies file bytes.
- **SSE chat streaming.** `chatApi.sendMessage` returns the raw `Response`.
- **Anthropic-only AI** — no provider abstraction.
- **Single EC2 SPOF.** No replica, failover, or autoscaling.
- **Single-worker scheduler.** Two workers would double-fire reminders/digests.
- **Inline-style frontend convention** on dashboard components (deliberate — avoids Tailwind v4 arbitrary-value compile bug).
- **Admin is a separate auth realm.** `admin_users` not joined to `users`.
- **Stripe idempotency by event ID only.** No body retained for replay.
- **`tasks.updated_at` is the proxy for completion time.** No `completed_at` field.
- **`/inbound/*` nginx block is critical.** Without it, webhooks fall through to the frontend and 500.
- **Forwarding addresses stored + matched lowercase** (Outlook lowercases recipients on send).
- **No background queue.** Extraction and emails are `asyncio.create_task` only.
- **Auto-deploy on master = no staging.** Every commit is production.
